# Open Health Data: Claude Code instructions

Start by reading `HANDOFF.md` in this folder. It has the full state of the project, decisions, IDs, the current blocker and next steps.

## Working style
- Small steps. Capture real data and look at the fields with the user before designing or building larger pieces.
- Explain briefly what you're about to do and what changed.

## Rules
- Never mark the Epic app "Ready for Production" without the user's explicit go-ahead. It locks the app.
- Never enter passwords; the user logs in to MyChart and fhir.epic.com themselves.
- Never write OAuth tokens to code, git, logs or the database. Use the macOS keychain (`keyring`).
- Never commit `epic_raw/`, databases or real health data (see `.gitignore`).
- Save raw API responses unchanged before processing. Store times in UTC.
- Keep the 14 osteosarc.com lab columns, plus the added columns listed in `HANDOFF.md` §6.
- `epic_pull.py` in this folder is the canonical version of the script. It also saves doctors' notes (`clinical_notes_p*.json` + text in `<pull>/notes/`, listed in `notes_index.json`; `--notes none` to skip) and imaging report text (`<pull>/binaries/`; `--report-text`). Turn notes into searchable text with `python3 -I ../records/notes2text.py <pull> ../records/<site>_notes_<date>/`.

## After every pull (do this without being asked)
1. Rebuild: `python3 flatten_labs.py && python3 flatten_vitals.py && python3 flatten_meds.py && python3 make_lab_view.py`
2. Run `python3 check_new_data.py` and work through what it lists:
   - **Drugs needing a half-life:** look each up on its US label (DailyMed, section 12.3), and add a row to `reference/med_halflife.tsv` with the label sentence, link and date (basis `label`). If no label states one, add a best estimate (basis `estimate`, reasoning in `refers_to`; the viewer draws these grey and dotted). If a half-life doesn't apply (IV fluids, flushes, local/topical use, vaccines), add basis `none` with the reason.
   - **Drugs with no class rule:** add a rule to `reference/med_classes.tsv`.
   - **New lab tests at only one hospital:** check whether another hospital has the same test under another code or name; join true matches in `reference/lab_concepts.tsv` (keep different formulas or methods apart). Give new tests an abbreviation/full name in `reference/lab_names.tsv` where useful.
   - **Sensitive drugs** (e.g. reproductive or obstetric): put their class and half-life rows in the private `local/med_classes.local.tsv` / `local/med_halflife.local.tsv`, never in `reference/`.
3. Rebuild again, check the viewer, then `python3 check_new_data.py --mark-reviewed`.
4. Tell the user what was added, what was estimated and what was skipped.

## Values typed from paper records
- Results that never came through a FHIR pull (a handwritten office chart, a faxed report) go in private files beside the tables: `local/vitals_manual*.tsv` and `local/labs_manual*.tsv` (same columns as `vitals_all.tsv` / `labs_all.tsv`; a blood pressure is two rows sharing one `result_id`; give LOINC codes so they join other hospitals' charts) and `local/meds_manual*.json` (a list shaped like `med_edits.json` "added", each with a `source`). The flatten scripts add them on every rebuild. Keep the script that writes them next to the typed record (e.g. `../records/obgyn_2021_2026-11-27/review/stage_obgyn_rows.py`). Don't re-enter what a FHIR pull already has.

## New Natera (Signatera) files
- Extract a new report PDF with `swift ../records/pdftext.swift in.pdf out.txt`, add the text path to `local/mrd_sources.json`, save emailed allele .xlsx files in its `allele_dir`, then run `python3 flatten_mrd.py`. If it says "new variants", run `python3 liftover_mrd.py --ensembl --genes` (sends only chromosome, position and base to Ensembl). Then `python3 make_lab_view.py`.
- Northstar Response (BillionToOne) reports: extract the same way and add the text path to `northstar_reports` in `local/mrd_sources.json`. flatten_mrd.py writes them into mrd_tests.tsv as `test="Northstar Response"` (Tumor Methylation Score, unit TMS). make_lab_view.py keeps them out of the Signatera panels (`D.mrd.rows` is Signatera only; Northstar is in `D.mrd.other`). Never plot a TMS on the MTM/mL axis. The viewer shows them in their own panel `mrd:ns` ("Northstar Response · Over time", mrd_view.js `northstar()`): log scale, reportable range <10 shaded, the lab's call in the tooltip; a card on the MRD full page, its own Library group under MRD tests (Compare tick), and a minimized bar (▲ log / ▲ linear).

## Viewer
- Serve it with `python3 serve_viewer.py` (port 8766, this Mac only; `--lan` for the home Wi-Fi). Don't use `python3 -m http.server` for it any more: that lists every private file in `local/` and doesn't save shared edits.
- Link previews: serve_viewer.py puts a title, description and picture (Open Graph tags, `with_preview`) right after `<head>` on the records page (/), /pathology-slides and /story, so a sent link shows a card. The pictures are plain title cards with no health data in `preview/` (made by `make_preview_cards.py`, Pillow: `../imaging/.venv/bin/python -I make_preview_cards.py`); `/favicon.ico` and `/apple-touch-icon.png` come from there too. A card made from a real photo (`make_preview_cards.py --photo slides <jpg>`) is health data, so it is written to private `local/preview/` and served ahead of the plain card; the slides card is Erica's 2023 HER2 stain (`local/pathology/b2023/full/her2_1_013.jpg`). Apps that fetch previews from their own servers (WhatsApp, Slack) may still skip a bare http IP:port address.
- Usage stats and a health meter: `/stats` on the viewer (this Mac and the home network only; `usage.py`, `usage.js`, `stats_view.html`). Visits are logged to the private `local/usage.sqlite`; the page reports only control/panel code names, never health values or Ask text.
- Start view (what a new visitor lands on): the "Start view" button next to Clear saves the current view to private `local/start_view.json` (this Mac and the home network only; `start_view.js`, injected by `serve_viewer.py`). Browsers that already have their own view keep it until they use "Put this browser back".
- Top bar fold (`navfold.js`, built into the page): on phones the pinned bar starts folded to one line (time window + Controls ▾); ▴ Fold folds it anywhere. A Keyframes panel pinned to the top bar folds to its title line once you scroll into the charts (click to open; folds again after ~150 px). Fold choice is kept in localStorage `navfold.*`, not in the Start view.
- Phones (narrow screens, 760 px and under; `make_lab_view.py`, `lesion_trends_view.js`, `imaging_view.js`): no part of the page may be wider than the screen (a chart panel's header wraps: title, then its buttons on their own line; the slice viewer's lesion list goes under the picture). The shared time axis thins its month labels to what fits (`plotPx()` in `ticks()`). On a device with no hover a chart answers a tap, not a moving finger (`Chart.defaults.events` without the touch events), and a finger cannot drag a panel by its title bar (use ⤒ ↑ ↓ ⤓). Hover boxes are drawn inside the chart, so their lines are wrapped to the chart's width (`fitTip`). To check: the built-in browser's phone size, then `document.documentElement.scrollWidth` must equal the screen width with every panel open.
- Sideways phones (script after the viewport tag in make_lab_view.py): a phone in landscape (short side of the screen 500 px or less) gets `width=1200`, so it shows the computer layout scaled to fit (pinch zoom works); upright it is the phone layout; switches when the phone turns. `?fit=wide` / `?fit=phone` force one. Sideways (`html.fitwide`): the top bar starts folded and folds itself again after 150 px of scrolling (navfold.js, key `navfold.side`), the open bar is capped at 58% of the screen height and a pinned Keyframes panel shows only its title line (tap it for the tracks), the Library starts hidden (`libhidden.side`, with a ☰ Library button on the folded bar), charts you haven't resized get at most the screen height less 170 px (`hOf`), and the page snaps gently to panel tops.
- Phone fit (`phone_fit.js`, built in after navfold.js; phones only, 760 px and under): narrower page and panel margins; in title bars "💬 Ask questions" becomes "💬" and the move (⤒ ↑ ↓ ⤓) and height (− +) buttons sit behind one "⋯"; the Treatments "changes · shared" line is hidden; smaller buttons, selects and tables; notes and colour keys taller than ~3 lines fold to 2 (tap or "▾ more" / "▾ show the key"); tables taller than ~320 px show the first ~260 px with "▾ show all N rows"; lesion chips scroll in one line. A MutationObserver re-applies after panels redraw. Warning boxes (e.g. swelling's "Shows large effects only") are left open on purpose. On a computer nothing changes.
- Phone start screen (`phone_view.js`, `make_phone_model.py`): on phones (760 px and under, page opened without a #link; `?phone=1` forces it, `?phone=0` skips it) the page opens on a turning glass head with the lesions playing through every viewer scan, the lesion volume chart (each lesion + Total; hollow circle = scan with no outlines), cards (Latest MRI opens the slice viewer on the newest scan via `window.openMriViewer`, Signatera, Treatments, Labs) and "Explore the records →"; a 🧠 3D button brings it back. The scans always keep playing; drag turns and pinch zooms, and the turning starts again 4 s after letting go. It is a smooth timelapse: a playhead moves through time and each lesion's shape morphs point by point between measured scans (make_phone_model.py fits one shared sphere layout to every outline: centre + radius per direction; an even blend, labelled "between scans"; scans with no outlines are passed through, not used as zero). Head, brain envelope, blood vessels (Frangi vesselness on the median of every measured contrast scan, reduced to centre lines with a thickness; the phone builds tubes), eyes (dark round globes) and optic nerves (least-cost path from each eye to the chiasm) all come from that median. The bottom chart is the viewer's lesion Volume chart: one line per lesion (lesion_series.measured + states, first series per visit; a "not seen / too small" state drops the line to the bottom with ×, dotted; from a no-outline point it is faint and dashed and has no playhead dot), a white Total line, log/linear button (localStorage phone.scale). Optic radiations: `make_phone_tracts.py <volumetry dir> <date>=<dti_files.txt> ...` fits a diffusion tensor to a raw "Ax DTI" series (b in (0019,100c), direction in (0019,100e); repeats averaged), tracks fibres and keeps those running from near the LGN (23 mm to the side of and 20 mm behind the traced chiasm) to the back 40 mm of the brain; the optic tracts (chiasm → LGN) are drawn, too thin for 5 mm DTI. Run it with `<volumetry dir> <date>=<files.txt> ...` for every DTI date (Siemens and GE; each date's axis frame is chosen by the longest fibres, `--swaps` also tries axis orders; dates not named are kept); the phone shows the radiations of the DTI nearest in time to the playhead, labelled with its date. Before the first scan with lesions the lesions grow from the last clean scan along the viewer's growth model (IMG_DATA.growth.backcast, middle doubling time; dotted on the chart, labelled "estimated growth"). Writes private `local/phone/tracts.json` and adds it to model.json (make_phone_model.py also picks it up). Layer buttons (localStorage phone.layers): Lesions, Vessels, Eyes & vision pathway, Skin, Brain, ☢ Radiation (lesions an SRS course aimed at, from IMG_DATA.dose.rows, glow amber; the brain glows during whole-brain radiation; fades over 40 days), ◫ Gravity grid (off by default; an illustration, labelled so: a 3D lattice pulled toward each lesion by its blended size). Model: `imaging/.venv/bin/python -I make_phone_model.py` → private `local/phone/model.json` (face cut away; served at `/phone/model.json`); the page includes the screen only when that file exists. three.js r128 from cdnjs.
- Panels: every panel header ends with the same group at the right, ⤒ ↑ ↓ ⤓ · − + · ▾ Minimize · × (one button size for all header buttons). Minimized panels are kept in the `mins` setting (part of the Start view). The Keyframes panel has a time scroll bar at its bottom (drag to move the window, click to jump; always shown, full width on All).
- Minimized panels show a data "skin" behind their title bar (make_lab_view.py: skinData / skinDraw), on the shared time axis edge to edge; each has a style button (labs line/mountain; Signatera mountain / stems / circles…; Procedures one row / lanes / activity; MRI lesions linear/log, dose stacked, perfusion highest lesion, swelling lines, scan dates 3T tall, slice viewer filmstrip from local/imaging/thumbs). Hover shows what a mark is. Top bar: Maximize all / Minimize all / × All; drag a panel's title bar to reorder (mouse or pen; not by touch); one bad panel can't stop the others (error message instead).
- Go to a date + locked cursor (`goToDate` / `setLock` in make_lab_view.py): the Middle calendar, a photo's "Show this date on the charts", story links (`#date=`), Keyframes ◀ ▶ and ⌖ Find centre the charts on the date and lock a blue cursor line there on every timeline chart and minimized bar. The lock stays on its date through zoom (zoom keeps it in the middle), drags and the sliders; 📍 Lock cursor (next to Middle) pins it at the middle, Shift-click a chart or L while pointing moves it, the 📍 date button centres it again, × unlocks. Kept in the `lock` setting. Panels follow it through the `ohd:date` event: the Brain MRI slice viewer loads the latest scan on or before the date and shows "No brain MRI yet" before the first scan; the minimized filmstrip outlines that scan.
- Panel settings rows move up into the title row when they fit (liftTools); tables under charts fold with ▾ Table; From / To have − / + and fine knob dragging.
- Story page ("Tell your story", `story_view.html` + `story.py`, at `/story`, this Mac and the home network/VPN only): Erica looks at a photo and talks; each answer is saved as WAV in `local/story/sessions/<id>/takes/`, turned into text on this Mac by `local/story/Story Transcribe.app` (built by `story/build_transcribe.sh`; rebuilding it makes macOS ask for Speech Recognition permission again), and Claude asks one spoken follow-up (chat server `POST /api/interview`, voice by `say`). A Ready check (button on the start screen; GET /story/api/health for the home Mac: drive, photos, speech to text tried on a spoken sample, Claude's voice, chat server, certificate; plus this computer's mic, speakers, connection, a practice run through POST /story/api/practice, and a filming-day list) should be all ✓ before Erica starts. "📚 Your stories" (start screen) shows progress by chapter (click a photo to tell or edit it), drafts waiting for review, saved stories and all sessions; the story editor changes title, caption, who sees it, fixes words in her answers (recordings unchanged), adds links (labs.html#date=YYYY-MM-DD opens the charts there) and more photos, or takes a story off the gallery (kept in local/story/check/deleted-stories.jsonl).
